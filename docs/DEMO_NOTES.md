# Attract-mode demos vs. our patches (findings)

Demos replay recorded pad input against the real game, so any change in timing, collision or button meaning makes them drift ("wonky").
Test method: boot headless, record the demo player's position each frame for 40,000 frames (4 demos: levels 15, 12, 10, 33) and compare with the clean ROM. Tools: demo/ (build_all.sh), /tmp scripts.

## What broke them
1. **Fog hook in the level loader (80:86C8)**: even a bare `JML` pass-through there shifts timing enough to desync demo 1 within ~200 frames (the demos are cycle sensitive at level load). Fix: no hook at the loader; MarkFog (80:C07F frame hook) clears the fog lazily when no player is active (title/demo/game over) -> a player becomes active, or when the level number changes (`!need`/`!lvl` at 7F:FCA0/FCA2).
2. **Hitbox 150**: changes collisions, so a demo can never match. Fix: the routine at 80:BEC9 keeps the original 8/16 constants; the 12/24 copy lives at 80:FF68; `HbEntry` (83:FC00, called from the single caller 80:BDCC) picks one by `$1EB4` (demo flag, set by the demo launcher at 80:9AB0).
3. **Radar button**: the demos contain recorded L presses (radar toggle). Reverse Fire / Reverse Inventory move the radar to Select, so the press did nothing and the demo drifted (first at ~frame 17,450 of the level-12 demo). Fix: `RadarCur/RadarPrev` (83:FC40) use the original $0030 mask while `$1EB4` is set.
4. MarkFog returns almost immediately during demos (constant ~21 extra cycles), and the skip-intro Start latch is an NMI *callback* (unregisters itself after the logos), so it costs nothing in demos.

## Result
All four demos plus the title loop match the clean ROM frame-for-frame over 40,000 frames.
Note: independent of our patches, ordinary code additions in hot paths can desync the demos; always re-run the 40,000-frame comparison after adding hooks.

## Border garbage = patching an already-patched ROM
A user state showed noise in the border/arrow glyph chars. Root cause: the IPS only wrote bytes that differ from the clean ROM, so zero bytes in the 2 MB expansion (GlyphTab has zero words) were never written. Applied over a ROM carrying an OLDER pause-map build, stale bytes survived (OR-looking garbage; identical 26-word mismatch reproduced). Legacy sites also stayed stale (old fog hook at 80:86C8, hitbox constants at 80:BEF8-BF09; the latter desyncs demos).
Fix (demo/mkfinal.py): in the expansion area write complete spans (gap 64, zeros included) and always write the legacy hook/constant sites. Verified: older-build ROM + new IPS == clean ROM + new IPS (byte-identical apart from checksum). Still recommend patching a clean ROM.

## Map legend v6m
Top row: active players only. Bottom-left: row 24 `LEVEL n`, row 26 `[swatch] n/total LEFT TO SAVE` (or `ALL total SAVED` at zero; nothing if the level has no victims). Row 25 is a spacer; rows 22-23 cols 15-16 belong to the down arrow, so text must stay out of that spot.

## Fog wipe on map reopen (fixed)
`!need`/`!lvl` were at 7F:FCA0/FCA2, inside the 24-byte palette buffer `!pbuf` (7F:FC90-FCA7). Opening the map overwrote `!lvl`, so the next MarkFog saw a "new level" and cleared the explored area. Moved to 7F:FCC0/FCC2. Test: walk, pause, map, exit, map again; explored-cell count must stay constant (old build 40 -> 25, new 40 -> 40). Keep new WRAM variables clear of FC90-FCA7 and FCB0-FCB9 (HDMA table).

## Pause screen: dimmed radar + item easter egg (v7)

**Radar dimmed in pause.** The original pause patch left CGRAM 16-31 (all HUD palettes) and color 178 (radar frame) undimmed so the radar looked live, but Select now opens the map instead of toggling the radar. Changes (all in `map/map.asm`):
- `BE:80EF`: the color-178 exemption is NOPed, so the frame dims like the rest of the screen.
- `BE:810D` -> `PalFix`: runs inside the dim-palette builder, before the NMI callback is registered (no race). Palette 4 (colors 16-19, unused by the HUD and the playfield) gets a halved copy of palette 7, then `RadarSwap` moves the radar cells (HUD tilemap rows 6-13) from palette 7 to palette 4. The inventory numbers share palette 7 and stay bright.
- `BE:8077` -> `PalOut`: on unpause the radar cells go back to palette 7; the existing exit callback restores the palette from the shadow, which was never modified.
- `RadarSwap` uses forced blank with NMI off, reads VRAM with the `DetectVram` dummy-read handling, and one scratch row buffer at `7F:FB80`.
- `BE:8174` is now `BRA $817E`: L/R no longer toggle the radar in pause (they spawned the radar task, which would have undimmed it). Weapon/item cycling (B/Y/A/X) is untouched.
- Verified: radar dims in 1P/2P, tilemap and CGRAM identical after unpause, map open/close inside pause leaves state intact.

**Easter egg: A+B+L+R+Select on the map** (the old plain-A fog toggle is gone). Each time all five buttons are down (A+B+L+R+Select replaced A+B+X+Y+Start: a Retro-bit Genesis/Saturn USB pad cannot report Y+Start with A+B+X, it drops buttons and adds a phantom Select) and the last one was pressed this frame, the map steps normal -> whole map (fog off) -> whole map + white 1-px item dots -> normal. The combo takes precedence over Select closing the map. Every map visit starts at normal (`!egg`=0, `!fogon`=1).
- Items come from the live level arrays: flags `7E:1EC4+2i` (bit 15 = collected, `$C000` = end), x `7E:6D02`, y `7E:6D48`.
- Dots use palette 2 (CGRAM 8-11, saved/restored), a copy of the map palette with color 3 = white.
- Marker list moved to `7F:F000` with room for 120 markers (worst case over all 55 levels is 2 players x 9 + 15 victims x 4 + 35 items = 113; 20 levels exceeded the old 84 limit). `7F:F000-F20F` is free: the VRAM backups end at `7F:EFFF` and the HUD backup starts at `7F:F210`.
- Marker order is players, victims, items and `Redraw` draws newest-first, so players/victims keep color priority when markers share a cell (an item next to a victim shows in the victim color).
- Refactor: `FogMk`, `Mk2x2`, `Mk1x1` replace the duplicated victim fog test.
- No timing window is needed: Select closes the map when it is released (`!sela` is armed by a new Select press and cleared when the chord fires), so the chord works in any press order and a chord never closes the map. The Select that opened the map is ignored.
- Redraw takes about 0.3 s, so hold the chord rather than tapping.

**Map exit buttons (v8).** Select closes the map and stays paused. Start closes the map and unpauses in one press (`!stx` flag; `MapCheck` then sets the Start bit in `$6E` so the pause loop sees it). The cheat chord was moved from Start to Select so an accidental Start can't unpause mid-chord.
**Legend layout (v11).** All legend text is centered on the 32-cell screen (`CenterCol`, `Dig`) and independent of the level width. Players on row 1, victims line (`n/total LEFT TO SAVE` / `ALL total SAVED`) on row 3, `LEVEL n` on row 26; a blank row separates text rows from the arrows. The map panel now starts one row lower (`!r0` base 8): up arrow rows 5-6, down arrow rows 23-24, left/right arrows rows 14-15.

**Slash glyph (v12).** The `/` in `n/total` is now 7 rows tall like the digits, with one pixel step per row (x = 6,5,4,3,3,2,1; Bresenham for dx 5, dy 6) and the same color banding as the font (orange rows 0-1 and 4-6, light rows 2-3). It was 8 rows tall with uneven steps and the top four rows in the light color.

## Character select: laugh -> password confirm sound (`ZAMN_CharSelect_ConfirmSound.ips`)
Sound commands go through `JSL $80CC3B` with the sound id in A (APU port 1 shows the id: `$27` = evil laugh, `$0E` = left/right chirp, `$05` = password confirm). Three sites load `LDA #$0027`:
- `80:9735` (file `0x1735`): the title screen Start. Kept, so the laugh still plays once there.
- `80:995A` (file `0x195A`) and `80:9991` (file `0x1991`): the character select confirm for player 1 and player 2.
The patch changes only the immediate's low byte at file `0x195B` and `0x1992` from `$27` to `$05` (two 1-byte IPS records). It touches nothing in the expansion area, so it works on the 1 MB ROM and on top of any of the other patches. It does not rewrite the header checksum, so apply it in any order; emulators ignore the checksum.
Verified by logging APU port 1: title Start `$27`, left/right `$0E`, confirm `$05`, for 1P and 2P, on the clean ROM and on the full stack.
The combined patch (`ZAMN_PauseMap_ReverseFire_RevInv_Hitbox150_Blood_SkipIntro.ips`) now includes this change (`demo/charselect.asm`, last step of `demo/build_all.sh`). Verified on the IPS applied to a clean ROM: title Start `$27`, confirm `$05`, and the map/pause/radar checks still pass.

**Exit door on the map (v9).** The exit is not part of the level data: when the last victim is saved, the task at 82:F70B (one per player, spawned from 80:8544) calls 82:F8D9, which creates an object of type $37 (the "EXIT" door) 32 px in front of the player. Touching it runs the player's state at 80:FAF0 and sets `$1FB8,X`; the level ends when every player has done so. Because the position is only known at that moment, `org $82F8DD` (was `STA $08 / LDA $00`) now does `JSL ExitHook`, which stores the door's x/y (task DP `$00`/`$02`) per player slot (`$06` & 2) at `!exx`/`!exy` (7F:FCD2-CD5 / CD6-CD9). `ClearFogBody` zeroes them on a new level or game. `BuildMk` draws a 2x2 marker for each stored door, after the players and before the victims (the door only exists once every victim is saved, so the marker cap is not affected). It respects the fog like the other markers. The marker uses the victim palette (5) and, while a door is recorded, its color 3 blinks yellow/white with the player markers (no victims exist then, so nothing else is affected; a first version used palette 1 in magenta, dropped to save a palette and its save/restore; palette 3 is the fog color). The legend's victims line becomes `[yellow swatch] EXIT` instead of `ALL n SAVED` once a door is recorded. Tested: 1P and 2P (two doors), level change clears, CGRAM identical after unpause, existing regressions unchanged (the 6 VRAM bytes at $8BC0 that differ after map exit are the map's own char scratch and were there before).

**Smoother map scrolling (v10).** Panning used to redraw all 308 cells per 32/24-tile step (about 0.3 s each). Now one step = one cell (8 tiles) and only the cells that come into view are drawn. Each cell keeps a fixed character slot while the window moves over it: `slot = ((oy/8+row) mod hc)*wc + ((ox/8+col) mod wc)`, character number `$BD+slot` (`SetRing`/`RowBase`/`ColSlot`; `!oxm`/`!oym` = the window's offset in the ring). `RenderRange` draws any rectangle of window cells (one row or one column on a step, one row at a time for the full `Redraw`; markers are applied per range). `FlushChars` sends them in vblank (a full row is two DMAs, a column goes cell by cell). The tilemap is moved by copying the panel's whole tilemap block through rbuf with DMA reads of VRAM (`MoveWords`, 128 words at a time, same dummy-read rule as the backup code), then the damage is repaired: the two frame-bar columns, the new cell column/row (`!tbuf`) and the left/right (and, on a vertical step, up/down) arrows (`ArrowFlags` is worked out before the vblank, `ArrGroup` writes). Vertical step: one vblank, finishes at about scanline 248 of 261. Horizontal step: two vblanks (first blanks the column that is scrolling out and draws the new cells into its slots, so nothing shows a half-updated cell; second moves the tilemap), finishing at about line 245. Input: a new direction steps at once, then repeats after 12 frames and every 3 frames (`!rep`, `!pdir`), so a tap is one cell. Tests: `pan4.py`/`pan7.py` (after every step compare the displayed cells with a full redraw at the same origin, levels 1-12, cheat states 1 and 2, 2P: 0 mismatches), screenshot at open identical to the previous build, all earlier regressions unchanged. Timing was measured by latching the V counter after each stage in a temporary build.

**Fix: stale arrow/bar copies after a sideways step (v10.1).** The one-word tilemap shift also moves the left/right arrows and the frame bars, which sit in the same rows, so a copy was left one column aside (a doubled arrow and stray vertical lines, first seen on a level-9 save). `ShiftH` now blanks the columns that receive those copies (`BlankCol`, from the `!blk` buffer at 7F:FBC0: columns 1 and c0-2 going right; 4, 30 and c0+wc+1 going left) before the bars/new column/arrows are rewritten. The old self-check compared only panel cells, so it could not see this; `demo/pan8.py` now checks that every tilemap word outside the panel, bars and arrow columns is blank (old build: 2 stale words, new: 0, levels 1-12).
